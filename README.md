# Pharma+ — منصة رقمية لصيدلية (نسخة حقيقية مربوطة بـ Supabase)

منصة رقمية لصيدلية: موقع معلوماتي للزبائن (أدوية، خدمات، دليل صحي، فريق، تواصل) + لوحة تحكم Admin
حقيقية مربوطة بقاعدة بيانات **Supabase** (مجانية) بدل التخزين المحلي (localStorage).

## ما تغيّر عن النسخة التجريبية (Demo)

- **قاعدة البيانات**: كل المحتوى (الأدوية، الخدمات، الفريق، الإعلانات، الدليل الصحي، معلومات
  الصيدلية) محفوظ الآن فـ Supabase (PostgreSQL حقيقي)، وباقي بعد إعادة تشغيل المتصفح أو تبديل
  الجهاز — بدون أي ارتباط بمتصفح معين.
- **تسجيل دخول Admin حقيقي**: بدل `admin/admin123` الثابت فالكود، دابا تسجيل الدخول كيمر عبر
  **Supabase Auth** (بريد إلكتروني + كلمة مرور حقيقية، تقدر تبدلها فأي وقت من Admin → Settings).
- **رفع الصور**: فلوحة التحكم، تقدر ترفع صور حقيقية (للأدوية، الفريق، الدليل الصحي، معرض الصيدلية)
  مباشرة من جهازك، وتنحفظ فـ Supabase Storage — بلا حاجة لروابط صور خارجية.
- **الأمان (RLS)**: قاعدة البيانات معدة بـ Row Level Security — أي حد يقدر "يقرأ" الموقع، وغير
  الحساب المسجل دخوله (Admin) يقدر "يعدّل".

## 🚀 الإعداد الأول (خطوة بخطوة)

### 1) إنشاء مشروع Supabase (مجاني)

1. روح لـ https://supabase.com وسجل حساب (مجاني، بلا بطاقة بنكية).
2. **New project** → اختر اسم للمشروع + كلمة مرور لقاعدة البيانات (احفظها فبلاصة آمنة) + المنطقة
   الأقرب ليك.
3. تسنى شوية (1-2 دقيقة) حتى يتجهز المشروع.

### 2) إنشاء الجداول (Tables) + الأمان (RLS)

1. من القائمة الجانبية فـ Supabase، دخل لـ **SQL Editor**.
2. **New query**، نسخ محتوى ملف `supabase/schema.sql` (موجود فهاد المشروع) والصقه، ثم اضغط **Run**.
   - هاد الملف كيخلق كل الجداول، كيفعّل الأمان (RLS)، وكيخلق bucket ديال الصور.

### 3) تعبئة بيانات تجريبية (اختياري لكن مستحسن)

1. **New query** من جديد، نسخ محتوى ملف `supabase/seed.sql` والصقه، ثم **Run**.
   - هادشي غادي يعمر الموقع بـ 14 دواء، 6 خدمات، 5 موظفين، 4 إعلانات، 8 مقالات صحية — نفس بيانات
     العرض التوضيحي الأصلي — باش تبدا بموقع "معمر" وتبدل المحتوى شوية بشوية من لوحة التحكم بدل ما
     تبدا من الصفر.
2. إلا بغيتي تبدا من الصفر مباشرة (بلا بيانات تجريبية)، تصيفط هاد الخطوة وغادي يبقى الموقع فارغ ماعدا
   معلومات الصيدلية الأساسية (اللي كتنزاد أوتوماتيكيًا من `schema.sql`).

### 4) إنشاء حساب Admin (تسجيل الدخول للوحة التحكم)

1. من القائمة الجانبية فـ Supabase: **Authentication** → **Users** → **Add user** → **Create new user**.
2. دخل بريد إلكتروني وكلمة مرور (هادو غادي يكونو بيانات دخول لوحة التحكم `/admin`).
3. تأكد من "Auto Confirm User" مفعّل (باش ما يحتاجش تأكيد إيميل).

### 5) جلب مفاتيح الربط (API keys)

1. من **Project Settings** (⚙️) → **API**.
2. نسخ:
   - **Project URL** → غادي يكون `VITE_SUPABASE_URL`
   - **anon public key** → غادي يكون `VITE_SUPABASE_ANON_KEY`

### 6) التشغيل محليًا

```bash
npm install
cp .env.example .env
```

افتح ملف `.env` وحط فيه القيم اللي جبتي من الخطوة 5، ثم:

```bash
npm run dev
```

الموقع غادي يخدم على `http://localhost:5173`، ولوحة التحكم على `http://localhost:5173/admin`
(دخل بالبريد وكلمة المرور اللي صنعتي فالخطوة 4).

### 7) النشر على Netlify

1. ارفع المشروع لـ GitHub.
2. فـ Netlify: **New site from Git** → اختر الـ repo.
3. Netlify غادي يكتشف تلقائيًا `npm run build` و `dist` من `netlify.toml`.
4. **قبل ما تدير Deploy**، زيد Environment variables (Site settings → Environment variables):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. Deploy 🎉 — بعد كل تعديل فالكود ديرو push لـ GitHub وNetlify غادي يعاود ينشر أوتوماتيكيًا.

> ⚠️ لا تدير commit لملف `.env` بحال هو فـ Git (ملف `.gitignore` كيستثنيه أصلاً). المفتاح
> `anon key` معروف أنه "عمومي" (كيدخل للموقع فالمتصفح) — الحماية الحقيقية كاينة فـ RLS
> (Row Level Security) اللي عرّفناها فـ `schema.sql`، ماشي فإخفاء المفتاح.

## 🛠️ التقنيات

React 18 + Vite + React Router + **Supabase** (PostgreSQL + Auth + Storage) — بدون أي إطار CSS
خارجي (CSS مخصص بالكامل فـ `src/index.css`).

## 🗂️ بنية المشروع

```
supabase/
├── schema.sql         # الجداول + RLS + storage bucket (نفّذه أولاً)
└── seed.sql           # بيانات تجريبية جاهزة (نفّذه بعد schema.sql، اختياري)
src/
├── lib/supabaseClient.js   # عميل Supabase (يقرأ .env)
├── i18n/                   # الترجمة (ar/fr/en) + RTL/LTR
├── context/
│   ├── DataContext.jsx     # القراءة/الكتابة من Supabase (CRUD)
│   ├── AuthContext.jsx     # تسجيل الدخول عبر Supabase Auth
│   └── ThemeContext.jsx
├── components/
│   ├── layout/             # Navbar, Footer, SiteLayout
│   ├── common/              # بطاقات، Modal، Badges...
│   ├── home/                 # مكوّنات الصفحة الرئيسية
│   └── admin/                # Sidebar, ProtectedRoute, ImageUploadField, حقول متعددة اللغات
└── pages/
    ├── ... صفحات الموقع العامة
    └── admin/                # كل صفحات لوحة التحكم
```

## 🔑 دخول لوحة التحكم (Admin)

الرابط: `/admin`

بيانات الدخول هي البريد الإلكتروني وكلمة المرور اللي صنعتيهم فـ Supabase Authentication (خطوة 4
فالأعلى). تقدر تبدل كلمة المرور فأي وقت من **Admin → Settings**، وتقدر تزيد حسابات Admin إضافية
(لموظفين آخرين) من نفس صفحة Authentication → Users فـ Supabase.

## 💾 كيفاش كتتخزن البيانات دابا؟

كل التعديلات (إضافة/تعديل/حذف أدوية، خدمات، موظفين، صور...) كتتسجل مباشرة فـ Supabase
(PostgreSQL + Storage)، وكتبقى موجودة لأي حد كيزور الموقع من أي جهاز أو متصفح.
